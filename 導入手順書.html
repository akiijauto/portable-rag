導入手順書：ローカルRAG検索 と コントロールUI

版：2026-09-02　対象：業務用のノートPC（Windows、Python あり、管理者権限なし）
この手順書は A4 サイズで作成しています。画面で読む前提ですが、そのまま印刷もできます。

1. これは何をするものか

ソフトできること
ローカルRAG検索
rag_app.py		フォルダにある HTML 文書（約5,000件）を検索し、結果を「Gemini に貼る文章」「スプレッドシートに貼る表」「人が読む一覧」の3形式で出します。外部通信はしません。
コントロールUI
launcher.py		自分で作った .py / .bat をボタンとして並べ、クリックで実行します。ボタン名の下に説明を表示でき、大きさ（小・中・大）と並び（1〜3列）を変えられます。

2. 事前に確認すること（1分）

1スタートメニューで「cmd」と入力し、コマンドプロンプトを開く。
2次を入力して Enter。
python --version
Python 3.9.x 以上の数字が出れば OK。「認識されていません」と出る場合はPC の管理担当に Python の有無を確認してください（Microsoft Store 版 Python でも動きます）。

3. ファイルを業務PCに置く

1メールで受け取った portable-rag.zip を、ドキュメントなど自分のフォルダに保存する。
2zip を右クリック →「すべて展開」。展開先の例：C:\Users\（自分の名前）\Documents\portable-rag
3展開したフォルダを開き、次のファイルがあることを確認する。
build_index.bat   索引を作る（ダブルクリック）
run_search.bat    検索画面を開く（ダブルクリック）
launcher.bat      コントロールUI を開く（ダブルクリック）
config.json       検索対象フォルダの設定
README.html / 要件定義.html / 振り返り.html / 導入手順書.html
メールの添付で .bat が弾かれる場合があります。その時は zip の中の .bat を .txt に改名して送り、業務PCで元に戻してください。または .bat を使わず、コマンドプロンプトで python rag_app.py のように直接実行しても同じです。

4. 検索対象フォルダを設定する

1launcher.bat をダブルクリック。ブラウザでコントロールUI が開く。
2右側の「検索対象フォルダ」で「参照」を押し、HTML が入っているフォルダまで辿って「このフォルダにする」→「追加」。フォルダのパスが分かっていれば、欄に貼り付けて「追加」でもよい。複数のフォルダを見る場合は同じ操作を繰り返す。
3一覧に「対象ファイル ○○ 件」と出ることを確認する。0 件なら HTML が無いフォルダ、赤字で「フォルダが見つかりません」ならパスが違う。
4最初から入っている sample_docs（動作確認用サンプル）は「外す」で外す。残しておくとサンプル文書も検索結果に混ざる。
メモ帳で config.json の "source_dirs" を直接書いても同じです（例："source_dirs": ["G:/マイドライブ/業務文書"]、区切りは /）。コントロールUI は同じファイルを書き換えているだけです。
索引（index フォルダ）には文書の中身が入ります。Google ドライブの同期フォルダではなく、PC 内（既定の ./index）に置いたままにしてください。

5. 索引を作る（初回・文書を追加した時）

1build_index.bat をダブルクリック。黒い窓が開いて進行状況が出る。
2最後に次のような行が出れば完了。
追加 5000 / 更新 0 / 変更なし 0 / 削除 0  文書 5000 件, チャンク 17627 件  (33.5s)
5,000件で 30秒〜2分程度。2回目からは変更分だけなので数秒です。
3「ベクトル検索: 無効」と出ても正常です。キーワード検索だけで動きます（意味検索を試す場合は第8章）。

6. 検索する

1run_search.bat をダブルクリック。ブラウザで http://127.0.0.1:8765 が開く。
2検索語を入れて「検索」。例：返品 送料 負担（単語はスペース区切り）。
3上のタブで出力形式を切り替え、「コピー」を押す。
使いたい場面操作
ブラウザの Gemini に聞く「Gemini貼付用」→ コピー → Gemini の入力欄に貼り付けて送信。質問と根拠資料がセットで入っています。
スプレッドシートの AI 関数「スプレッドシート用(TSV)」→ コピー → シートの A1 に貼り付け（自動で列に分かれます）→ 別のセルに =AI("この資料を根拠に○○を答えて", A2:E9)
自分で過去事例を探す「閲覧」タブ。ファイル名のリンクで元の HTML が開きます。
4終わるときは黒い窓を閉じる（または Ctrl+C）。

7. コントロールUI を使う

1launcher.bat をダブルクリック。ブラウザで http://127.0.0.1:8766 が開き、「RAG 索引更新」「RAG 検索画面」の2つのボタンが最初から並んでいる。
2実行する：ボタンをクリック。別の黒い窓が開いてプログラムが動き、右側の「実行状況」に「起動しました」「終了（終了コード 0）」と出る。
3説明を見る：ボタンにマウスを乗せると右側の「説明」欄に表示される。ボタンの下にも常に表示される。
4自分のプログラムを追加する：右上「ボタンを編集」→ 右側の「フォルダから選ぶ」にプログラムのあるフォルダのパスを貼り付け →「一覧」→ ファイル名をクリック → ボタン名と説明を入力 →「保存」。
パスはエクスプローラーのアドレス欄をクリックしてコピーできます。
5並べ替え・削除：編集モード中、各ボタンの下の「↑ ↓ 編集 削除」。削除してもプログラムのファイルは消えません。
6大きさと並び：上部の「ボタンの大きさ：小・中・大」「並び：1列・2列・3列」。設定は launcher.json に自動保存され、次回も同じ配置で開きます。
動かせるのは .py と .bat（.cmd）だけです。.py はコントロールUI と同じ Python で実行されます。

7-2. 系列まとめ（NotebookLM / Gemini に渡す中間ファイル）

NotebookLM は 300 ソース、Gemini は 10 ファイルまでです。文書を「系列」ごとにまとめ、上限に収まる大きなファイルと、Gemini に要約させる依頼文を作ります。

1bundle.bat をダブルクリック（またはコントロールUIの「系列まとめ」ボタン）。
2黒い窓の質問に番号で答える。系列の決め方は「1 フォルダごと / 2 ファイル名の規則 / 3 文書内の項目（顧客名など） / 4 検索結果」。モードは「1 単純結合 / 2 要約依頼 / 3 両方」。
3bundles フォルダに系列ごとのフォルダができる。bundles/index.html を開くと件数と分割数の一覧。
4要約を作る：summary_prompt の中のテキストを 1 つずつ Gemini に貼る → 返ってきた要約を （系列名）_要約.md に貼って保存。この .md を検索対象フォルダに置くと RAG でも検索できます。
5全文を渡す：notebooklm のファイルを NotebookLM のソースに、gemini のファイルを Gemini チャットに添付。
一覧に ⚠ が出た系列は上限で打ち切られています。系列をさらに細かく分けるか、「定型行を除く」を y にして小さくしてください。

8. 意味検索を試す（任意・pip が使える場合）

1コマンドプロンプトで portable-rag フォルダに移動し、
pip install -r requirements-optional.txt
2build_index.bat を再実行。初回は約120MBのモデルがダウンロードされ、続けてベクトル化が始まる（5,000件で数分〜数十分）。
3検索画面の「ハイブリッド」がキーワード＋意味検索。効果が無ければ config.json の "use_embeddings" を "false" にすると元に戻ります。

9. 困ったとき

症状対処
bat をダブルクリックしても一瞬で閉じるコマンドプロンプトでフォルダに移動し python rag_app.py と打つとエラー内容が見えます。
「フォルダが見つかりません」コントロールUI の「検索対象フォルダ」で赤字のフォルダを「外す」→「参照」で選び直す。config.json を直接書いた場合は \ を / に。
検索結果が 0 件索引を作っていない可能性。build_index.bat を実行。
文字化けUTF-8 と Shift_JIS は自動判定。それ以外は README.html の FAQ を参照。
ポートが使用中と出るconfig.json の web_port（検索）、python launcher.py --port 8777（コントロールUI）で変更。
索引を作り直したいindex フォルダを自分で削除してから build_index.bat。
